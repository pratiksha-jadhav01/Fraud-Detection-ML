
# Technical Documentation

## 1. Project Title
Machine Learning in Detecting Financial Fraud

## 2. Problem Statement
Financial fraud involves unauthorized or suspicious transactions that can cause financial losses. Machine learning techniques can analyze transaction-related features and classify transactions as legitimate or potentially fraudulent.

## 3. Objectives
- Develop a prototype for financial fraud detection.
- Apply data preprocessing techniques.
- Address class imbalance using SMOTE on training data.
- Train and compare multiple machine learning models.
- Evaluate model performance using classification metrics.
- Maintain project files and results using GitHub.
- Support reproducibility through documentation and dependency management.

## 6. Dataset Description
The project uses a synthetic dataset containing 1,000 transaction records and 15 columns. The target column is `FraudIndicator`, where 0 represents a legitimate transaction and 1 represents a potentially fraudulent transaction.

The dataset is intended for prototype development and does not establish real-world fraud detection performance.

## 7. System Architecture

The prototype follows this workflow:

Dataset
    ↓
Data Inspection and Preprocessing
    ↓
Feature Preparation
    ↓
Stratified Train-Test Split
    ↓
SMOTE on Training Data Only
    ↓
Model Training
    ├── Logistic Regression
    ├── Decision Tree
    └── Random Forest
    ↓
Prediction on Test Data
    ↓
Performance Evaluation
    ↓
Model Comparison and Results

## 8. Methodology
1. Load the dataset and inspect its structure.
2. Prepare the input features and target variable.
3. Perform preprocessing and feature preparation.
4. Split the data into training and testing sets using stratification.
5. Apply SMOTE only to the training data to address class imbalance.
6. Train Logistic Regression, Decision Tree, and Random Forest models.
7. Generate predictions on the held-out test set.
8. Evaluate the models using accuracy, precision, recall, and F1-score.
9. Compare the results to identify the strongest model on the test split.

## 13. Results
The recorded experiment evaluated Logistic Regression, Decision Tree, and Random Forest on a held-out test set of 200 transactions.

| Model | Accuracy | Fraud Precision | Fraud Recall | Fraud F1-score |
|---|---:|---:|---:|---:|
| Logistic Regression | 71.50% | 11.29% | 77.78% | 19.72% |
| Decision Tree | 90.00% | 26.09% | 66.67% | 37.50% |
| Random Forest | 97.00% | 66.67% | 66.67% | 66.67% |

Random Forest achieved the highest accuracy and fraud-class F1-score among these three models on the recorded test split.

These results are from a synthetic dataset and a single test split. They should not be interpreted as evidence of performance on real-world financial transactions.

## 14. Limitations
- The dataset is synthetic and may not represent real-world fraud patterns.
- Only a small number of fraudulent examples are present in the test set.
- Results from one train-test split may vary with different data splits.
- High accuracy alone does not guarantee reliable fraud detection.
- Separate reusable source modules and automated tests are planned but are not yet implemented.
- The prototype is intended for educational and research purposes, not production deployment.
